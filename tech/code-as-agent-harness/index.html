01 Section

Introduction & Problem Framing

code는 더 이상 LLM의 출력 결과물이 아니라 agent가 reasoning, acting, verifying하는 operational substrate이다.

The Shift

Code: 출력에서 실행 기반으로

LLM은 competitive programming에서 repository-level SWE까지 강력한 code 능력을 보여왔다. 하지만 agentic system에서 code는 단순한 target output를 넘어, agent가 reasoning·acting·environment modeling·verification을 수행하는 operational substrate로 자리 잡고 있다.

Program-aided reasoning: 중간 계산을 executable code로 externalize (PAL, PoT)
Robotic/embodied agents: 생성된 program = 실행 가능한 policy (SayCan, CaP, Voyager)
SWE 환경: codebase·execution traces·tests·runtime feedback = environment state
→ code는 executable, inspectable, stateful medium
Conceptual Framing

세 가지 coupling element

Agent harness = stateless model을 functional agent로 만드는 software layer (tools, APIs, sandboxes, memory, validators, permission boundaries, execution loops, feedback channels). 논문은 long-running agentic system의 세 요소를 구분한다.

① Model-internal capabilities: reasoning, perception, planning, simulation, evaluation
② System-provided harness infrastructure: tools, APIs, sandboxes, memory, validators, permission boundaries, telemetry — harness engineering의 주 대상
③ Agent-initiated code artifacts: agent가 생성·실행·수정·persist·공유하는 interactive code 객체 — 기존 survey에서 underexplored
이 논문의 초점: ③ agent-initiated code artifacts가 ①②와 어떻게 상호작용하는가
Taxonomy

3-Layer Taxonomy of Code as Agent Harness

02 Section

Layer 1: Harness Interface

code가 agent와 task environment 사이의 기본 interface가 되는 방식 — reasoning, acting, environment modeling

§2.1 Code for Reasoning

추론을 executable & verifiable하게

Pure CoT는 reasoning과 computation을 모두 자연어로 처리 → 중간 상태를 harness가 verify할 수 없음. Code-for-reasoning은 model이 program을 생성하고 external runtime이 실행·평가하여, reasoning과 computation을 분리한다.

① Program-Delegated Reasoning: PoT, PAL — code로 계산을 위임, execution trace로 검증
② Formal Verification & Symbolic Reasoning: Lean, Isabelle, Coq — 기계 검증 가능한 formal proof language
③ Iterative Code-Grounded Reasoning: NExT, CodePRM, RLEF — generate→execute→verify→refine 폐루프
최근: EG-CFG (생성 중 execution signal 주입), R1-Code-Interpreter (다중 실행 세션)
§2.1 Reasoning Paradigms

세 가지 reasoning interface 비교

Program-Delegated
PoT, PAL, CodeAdapt Code로 계산 위임 Execution trace로 검증 단발성 task에 적합
Formal / Symbolic
SATLM, ReProver, Lean4Agent Lean, Coq 기반 formal proof 기계 검증 가능한 derivation Theorem proving 한계
Iterative
NExT, CodePRM, RLEF Generate→Exec→Verify→Refine RL로 trajectory 최적화 긴 horizon 비용
§2.2 Code for Acting

행동을 programmable하게

Code-for-reasoning과 달리, action은 부분 관찰·동적 환경에서 실행됨. failure가 invalid state transition, delayed feedback, silent error로 발생. 핵심 과제는 grounding: abstract output을 환경 제약에 맞는 executable behavior로 변환.

① Grounded Skill Selection: SayCan (affordance 기반), KnowNo (uncertainty-aware), BOSS (skill chain 합성)
② Programmatic Policy Generation: CaP (Python robot policy), RoboCodeX (multimodal tree), Code-BT (behavior tree)
③ Lifelong Code-Based Agents: Voyager (Minecraft skill library), UI-Voyager (GUI self-evolving), SkillsCrafter (continual learning)
AutoHarness: code harness 자동 합성으로 invalid action filtering
§2.3 Code for Environment

환경을 inspectable & modifiable하게

환경을 opaque external process로 두지 않고, simulator·repository·tests·traces·logs라는 computational artifact로 표현. 실행 가능한 환경 = verifiable state transition + persistent & modifiable representation.

① Structured World Representations: ViStruct, FactoredScenes, Code2World (renderable HTML)
② Execution-Trace World Modeling: SemCoder, CWM, WorldCoder (Python으로 world model 합성)
③ Code-Grounded Evaluation Environments: SWE-bench, AgentBench, InterCode, CRUXEval
④ Verifiable Environment Construction: SWE-smith, EnvScaler (환경 자체를 합성·검증)
03 Section

Layer 2: Harness Mechanisms

code가 agent loop에 들어온 뒤, 단일 generation step를 넘어 reliable하게 만드는 system layer — planning, memory, tool use, PEV loop, harness optimization

§3.1 Planning

계획 = harness control layer

Planning은 단순한 모델 내부 reasoning이 아니라, agent가 intent를 executable step으로 externalize하고 trajectory를 규제하는 harness 제어 장치. 4가지 유형으로 분류.

① Linear Decomposition: ReAct, Self-Planning, WebAgent — 순차적 step 분해 + 코드 생성
② Structure-Grounded: CodePlan (dependency graph), VerilogCoder (circuit graph), GraphCodeAgent (dual-graph)
③ Search-Based: Tree-of-Code, CodeTree, SWE-Search (MCTS), Meta-Harness — 후보 경로 탐색
④ Orchestration-Based: MapCoder, QualityFlow, NLAH (natural-language harness spec → runtime 해석)
최근: PLAN.md, AGENTS.md — filesystem-backed persistent planning object
§3.2 Memory & Context

상태 관리 layer: 단순 context window가 아님

Memory는 model context와 durable storage 사이에서 어떤 정보를 active에 두고, 무엇을 압축하고, 무엇을 외부에 offload할지 결정하는 state-management layer. 장기 SWE task에서 context 폭발, 반복 localization, local consistency 붕괴를 방지.

① Working Memory: SWE-agent, CodeMem — 현재 trajectory의 active control surface
② Semantic Memory: AutoCodeRover, RepoCoder — repository를 queryable evidence space로
③ Experiential Memory: MemGovern, ExpeL — cross-task transfer용 trajectory·reflection
④ Long-Term Memory: MemCoder, TALM — validated experience의 compact한 보존
⑤ Multi-Agent Memory: MIRIX, ChatDev — shared blackboard / collaborative state graph
+ Context Compaction & State Offloading: LongCodeZip, SWE-Pruner, SWEZZE
§3.3 Tool Use

도구 = governed interface

Tool use는 단순 부가 기능이 아니라 model intent와 external system 사이의 governed interface. 어떤 tool을 노출할지, 권한은 무엇인지, 실행 위치, 결과 정제, 위험 action의 human approval 등을 harness가 결정.

① Function-Oriented: ToolCoder, CodeQA, RAG-for-Code — API/doc 검색로 knowledge gap 해소
② Environment-Interaction: CodeAgent, SWE-agent — repo·shell·test 직접 조작
③ Verification-Driven: AgentCoder, VeriGuard — test·static analysis·fuzzer로 deterministic feedback
④ Workflow-Orchestration: MapCoder, OpenHands — multi-tool·role·policy를 통합 workflow로
Lifecycle hooks: pre-use (permission check), post-use (sanitize, compact, memory update)
§3.4 PEV Loop

Plan → Execute → Verify Control Loop

harness = cybernetic governor: action 효과를 관찰하고 state transition을 규제
§3.5 Agentic Harness Engineering

harness 자체를 최적화 대상으로

AHE는 prompt engineering(지시 변경)도 context engineering(증거 변경)도 아닌, operating environment 자체를 분석·수정하는 문제. 많은 agent 실패가 model 생성 능력이 아니라 harness의 약점에서 비롯됨.

Deep Telemetry: prompt, tool args, sandbox snapshot, test result, decision tree, rejected alternatives, human intervention — 비교 진단의 기반
Evolution Agent: trajectory 관찰 → 실패 진단 → harness 수정 제안 → held-out task로 평가 → regression 없을 때만 promote
Governed Harness Mutation: permission boundary, network access, credential 변경은 HITL approval 필요. PEV loop 안에서 자신도 검증받음
산업 수렴: OpenAI, Anthropic, LangChain 모두 explicit harness loop + trace replay + eval suite 필요로 함
04 Section

Layer 3 & Beyond: Multi-Agent, Applications, Open Problems

단일 agent에서 multi-agent로, 그리고 실제 응용과 미해결 과제까지

§4.1 Multi-Agent Collaboration

역할 분화 & artifact 기반 조정

단일 agent의 한계: context window, specialization 부족, 자기 오류 검증 불가. Multi-agent는 역할 분화 + 공유 code artifact + 실행 feedback로 조정. code가 단순 출력이 아니라 planning·acting·verifying·개선의 shared substrate.

역할: Synthesis (Coder), Understanding (Navigator), Verification (Tester), Execution (Executor), Planning (Architect)
Meta-role: EvoMAC의 Gradient Agent (실패 원인 귀인) + Updating Agent (workflow DAG 수정)
Interaction Modes: ① Collaborative synthesis ② Critique & repair ③ Adversarial validation ④ Reasoning debate
SoA: Mother agent가 runtime에 subtask 복잡도에 따라 Child agent를 동적 spawn
§4.1.3 Workflow Topology

미리 정의된 vs 적응형 topology

Pre-defined Heuristic
Chain (Waterfall): ChatDev, MetaGPT Cyclic (Agile): AgentCoder (max 5 iter) Hierarchical: MAGIS, HyperAgent Star: CANDOR panel, MetaGPT pub-sub 고정 → 단순하지만 비적응적
Objective-Driven Adaptive
Dynamic pool scaling: SoA (복잡도별 agent spawn) Feedback-driven DAG: EvoMAC (실행 log로 graph 수정) Runtime self-reorg: SEW (workflow spec 진화) Query-level: FlowReasoner (task별 MAS 생성) 적응적이지만 복잡도 높음
Key Insight
Topology 복잡도 ∝ harness-state 비형식성 형식적 shared substrate → 단순 topology L2MAC: 가장 형식적 substrate + 가장 단순 chain implicit state → 복잡한 topology로 보상 성숙한 harness는 단순 protocol로 충분
§4.2-4.3 Shared Substrate

공유 code substrate & 수렴 기준

대다수 시스템이 implicit/file-only 표현에 머물러, agent간 state divergence를 감지 못함. code는 executable하므로 objective behavioral signal로 수렴 가능. 논문은 4수준 표현과 6가지 수렴 패턴을 식별.

4 표현 수준: ① Implicit/File-only (대다수) ② Repository-based (MAGIS, HyperAgent) ③ Execution-based (AgentCoder, MAGE) ④ Blackboard/Shared-State (L2MAC, Cogito)
6 수렴 패턴: Correctness (test-gated), Security (CWE+crash), Performance (runtime/memory), Score-based, Consensus (투표), Implicit (고정 iteration=가장 많지만 가장 약함)
핵심 gap: 대다수가 implicit state + implicit convergence → system 붕괴의 근원
제안: Shared Code-Centric Harness Substrate — repository + execution을 통합한 queryable 표현
§5.1.1-5.1.2 Applications (1)

Code Assistants & GUI/OS Agents

code-as-harness가 가장 가시적으로 구현되는 두 영역. Code assistant는 repository 전체를 operational workspace로 삼고, GUI/OS agent는 모든 관찰과 행동이 code로 표현되는 'program world'에서 동작.

Code Assistants: SWE-agent, OpenHands, Claude Code, Codex — repository + sandbox + PR workflow + 실행 feedback
산업: LingmaAgent (Alibaba) — 자율 해결 16.9%, 수동 개입 시 43.3%. Cursor Composer = online RL on 사용 trace
GUI/OS: 관찰 = DOM/AXTree/screenshot, 행동 = click(x,y)/type/scroll code, 평가 = Python evaluator script
Code2World: 다음 GUI state를 renderable HTML로 예측 — world model 자체가 executable artifact
프로덕션: Claude Computer Use, OpenAI Operator, Project Mariner, UI-TARS, AutoGLM
§5.1.3-5.1.5 Applications (2)

과학 발견, Embodied, Personalization

scientific method 자체가 hypothesize→design→execute→observe→revise의 폐루프이며, 각 단계가 program으로 표현 가능. Embodied는 code가 grounding interface이자 safety boundary. Personalization은 사용자 preference를 editable code artifact로.

Scientific: AI Scientist, Coscientist, Biomni, AlphaProof — hypothesis=program, 실험=script, 분석=notebook, lab=runtime
Self-Driving Lab: A-Lab (41 신물질 합성), Chemputer (XDL → hardware-independent), Coscientist (Suzuki coupling 자율 실행)
Embodied: SayCan, CaP, Voyager, Code-BT — code = control boundary + safety + reusable skill library
Personalization: preference state = editable artifact, feedback = policy adaptation, instruction-following = structured constraint
§5.2 Open Problems

6대 미해결 과제

① Evaluation
Harness-level metric 부재 End-task success가 model·harness·tool·env 혼합 Oracle adequacy 위기 Trajectory efficiency·replayability 필요
② Verification
Execution feedback ≠ 완전한 검증 약한 oracle → overconfident agent Verification stack with explicit scope Feedback calibration·independent verify 필요
③-⑥ 기타
③ Self-evolving: regression-free harness ④ Shared state: transactional semantics ⑤ Safety: HITL as durable harness state ⑥ Multimodal: visual grounding·compression
